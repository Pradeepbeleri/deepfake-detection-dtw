# Dataset acquisition and first baseline

Reviewed 7 November 2026. No labeled audio-video deepfake dataset is available in this workspace, and no real/fake training or held-out evaluation has been run. Repository code licenses are not dataset licenses. The recommendations below do not authorize accepting terms, redistribution or use of particular videos.

## Primary: FakeAVCeleb

The [official FakeAVCeleb repository](https://github.com/DASH-Lab/FakeAVCeleb) describes manipulated video and synthesized cloned audio. Its maintainers' table reports 500 real and 19,500 fake videos across 500 subjects and says rights were not cleared; these are provider-reported collection counts, **not** audited counts in this environment. The README says data is released through request forms and code under MIT; MIT code terms do not cover the data. Exact per-clip label definitions, source/target identity availability, audio/video provenance, data version, authorized storage, redistribution and live demonstration rights remain to be confirmed from the agreement and metadata.

**User action:** open the [official request form](https://docs.google.com/forms/u/1/d/e/1FAIpQLSfPDd3oV0auqmmWEgCSaTEQ6CGpFeB-ozQJ35x-B_0Xjd93bw/viewform); provide the requested academic affiliation, project/research purpose and contact information accurately; review and accept only the terms your institution permits; submit and wait for the authors' acceptance and download instructions. Ask the provider specifically about: model training, a local faculty demonstration, Colab/Drive or cloud processing, retention and private transfer, original-to-manipulated links, source/target identity mapping, audio and manipulation labels, and permitted subsets. Do not post credentials, provider download links, dataset videos or accepted agreements in public Git. We have not requested or received access.

## Parallel candidate: LAV-DF

The [official LAV-DF repository](https://github.com/ControlNet/LAV-DF) provides [OneDrive, Google Drive and Hugging Face links](https://github.com/ControlNet/LAV-DF#download) for a localized audio-visual forgery dataset. Its [dataset terms](https://github.com/ControlNet/LAV-DF/blob/master/TERMS_AND_CONDITIONS.md) permit non-commercial research and education subject to agreement, require agreement to the underlying VoxCeleb2 terms, and include a responsibility/indemnity provision. The repo code is CC BY-NC 4.0; do not substitute the code license for dataset terms. The [official metadata schema](https://github.com/ControlNet/LAV-DF/blob/master/dataset/lavdf.py) includes original linkage, video/audio modification flags, fake intervals and a split. Exact source/target identity completeness, audio lineage, class balance, size, and the feasibility and authorization of downloading a small subset remain unverified. The official Hugging Face host was blocked by this environment's policy.

**User action:** review the dataset and VoxCeleb2 agreements with the responsible institution and accept them only if authorized. If the terms permit, obtain an appropriately small initial subset and its complete provenance metadata from an official host, using the provider's supported instructions. Do not infer identities or labels from directory names alone. This is a plausible parallel route, not yet a cleared or confirmed small dataset. LAV-DF may share source identities with other VoxCeleb-derived data; audit actual overlaps before calling cross-dataset evaluation independent.

## Other candidates

- **DeepfakeTIMIT:** an authoritative current provider download agreement and its original-audio rights, source/target identity mapping and redistribution terms were not verified. An image/video face-swap collection alone does not establish a suitable manipulated audio-video benchmark. Request provider documentation before relying on it.
- [AV-Deepfake1M](https://github.com/ControlNet/AV-Deepfake1M): the official metadata describes real, visual-modified, audio-modified and both-modified labels, source links and manipulation intervals. The provider says the dataset requires a signed [EULA](https://github.com/ControlNet/AV-Deepfake1M/blob/master/eula.pdf); the full million-video scale is impractical for initial setup and permitted selective access is unverified. Consider later evaluation only after terms and identity overlap are resolved.
- [FaceForensics++](https://github.com/ondyari/FaceForensics) requires provider acceptance and separate data terms. Its [dataset instructions](https://github.com/ondyari/FaceForensics/blob/master/dataset/README.md#audio) say its downloaded source videos lack audio; reconstructing audio requires separately obtaining original YouTube material and validating timing and rights. It is not an immediate substitute for synchronized audio-video training.
- A small institutional collection is an alternative only if the participants consent, genuine and **actually manipulated** clips and their labels/source relationships can be verified, and the necessary media and manipulation rights permit research and demonstration. A few clips can test the pipeline but are not sufficient evidence of generalization. We found no independently verified, permissively licensed small labeled talking-face dataset that meets all requirements in this environment.

## Size, transfer and compute planning

FakeAVCeleb's actual archive/subset sizes and download layout were not verified; ask its provider before provisioning. The existing single 12-second extraction produced an approximately 2.6 MB compressed feature file and took about 40 seconds on this CPU. Purely as a rough linear capacity illustration, 20,000 similarly sized feature files would occupy about 52 GB and require about 222 CPU-hours of sequential extraction, excluding media, failures, overhead and variation. This is **not** a dataset benchmark or reliable forecast; sample rates, durations, compression and resource limits differ. The current workspace had about 56 GB free at inspection, so a full dataset plus features should not be assumed to fit. The trainer is CPU-only and full-batch and may exhaust RAM on a large set. This runtime exposed no `nvidia-smi`; GPU availability was not established. The DINOv2 extraction CLI can select CUDA only with a compatible installed GPU build and available device.

After the provider allows private transfer, stage media and metadata outside Git, such as `/workspace/deepfake-private/dataset/`. Use provider-approved private transfer rather than public Git or sharing links. The attachment transfer available in this session is limited to 32 MiB per file; larger approved archives require a supported private transfer or splitting and verified reassembly if the terms permit it. Avoid copying datasets into Colab or Google Drive unless the agreement and institution explicitly permit that service and location. The [Colab template](../notebooks/colab_baseline.ipynb) expects pre-extracted private data and is not yet tested in a Colab runtime; it does not download datasets.

## Minimum audit before first training

1. Record dataset name/version, access and permitted use, sample and manipulation labels, consent/rights evidence, exact MP4 and extracted feature paths, original/derivative relationships, and globally normalized source and target identities. Do not fabricate missing identities or clip-level labels from folder names. If metadata cannot support the schema in README, obtain clarification or exclude the sample; do not claim identity-disjointness.
2. Decode and extract permitted clips with the same verified encoder checkpoints. Check real/fake audio provenance, synchronization, face coverage, failures, and exact video-feature hashes. Include each source recording for cross-identity manipulations and keep the provider's metadata private.
3. Audit source and target identities, exact duplicates and source recording groups before making train/validation/test partitions. The code groups all linked identities, video IDs and source recordings, aims for 70/15/15 and rejects exact duplicates across splits; these checks cannot detect undeclared links or mislabeled clips. Report actual counts and class balance by video and partition. Require both classes in train and validation and reserve test for final evaluation.
4. Freeze version, feature/checkpoint hashes, split, seed and configuration. Select classifier weights by validation loss and the video-level operating threshold by validation balanced accuracy. Inspect data quality and validate correspondence before making synchronization claims. Run test evaluation once after decisions are frozen, report class counts, uncertainty and failures. No test-data metric is available yet.

## LAV-DF provisional workflow

The user reports access is granted. The current execution environment nevertheless returns an HTTP proxy 403 for `huggingface.co` and exposes no configured Hugging Face binding, so no dataset file or metadata could be fetched here. This is an environment connectivity observation, not a claim that the user's provider authorization failed. Do not paste tokens into chat or commit them. Use [the LAV-DF Colab workflow](../notebooks/lavdf_baseline.ipynb) with the user's interactive authenticated provider access and a private location only after the provider terms and institutional storage conditions are satisfied. The notebook is a prepared, unexecuted template; actual repository layout, available media, authentication and Colab compatibility have not been verified.

The official [dataset metadata type](https://github.com/ControlNet/LAV-DF/blob/master/dataset/lavdf.py) has `file`, `n_fakes`, `fake_periods`, `duration`, `original`, `modify_video`, `modify_audio`, `split`, frame counts and audio channels. Its [baseline code](https://github.com/ControlNet/LAV-DF/blob/master/model/batfd.py) treats either modification flag as a manipulated video. The importer maps `modify_audio or modify_video` to video-level `fake`; both false maps to `real`. It retains both flags, the provider's fake intervals, `original` link and provider split. This is a transparent video-level aggregation of segment-level labels, not a claim that the entire fake video is manipulated. It does not change source labels.

The metadata type does not establish source/target identity mapping, full consent or rights for each sample. The operator must supply a separately audited private `curated-provenance.json`, keyed by the provider `file`, containing `source_identity`, `target_identity` for fake records, `source_recordings` including the provider `original` for fakes, and `usage_rights`. Source/target IDs must be grounded in actual provider provenance and normalized across all selected data. Do not fill them with guesses, automatically treat the same person as source/target, or invent rights. If the provider metadata cannot establish them, request clarification and exclude affected records; the system cannot honestly call the evaluation identity-disjoint otherwise.

`python -m deepfake_dtw.lavdf` produces a private plan before download/extraction. It validates source flags and intervals, refuses unsafe paths and contradictory records, maps provider `train/dev/test` to `train/validation/test`, and refuses identity or recording links spanning provider splits. A seeded selection keeps whole connected identity/recording groups within the supplied curated sidecar, at most 60 videos per split by default, and requires both labels per split. Unlisted or incorrect provenance cannot be checked. This is a conservative bounded starting point, not a statistically powered or automatically representative sample; if no valid groups fit, it fails rather than guessing. Adjust the limit only after inspecting actual provider metadata. If different splits share identities or source recordings, request a correct identity-disjoint split rather than ignoring the error. Preserve every selected whole video: because LAV-DF manipulations can be localized, trimming could turn a video-level fake label into an incorrect clip label.

The Colab workflow lists official repository files after interactive Hugging Face login, asks the user to choose the exact metadata filename, downloads only selected videos when they are direct files, extracts with verified local Whisper/DINOv2 checkpoints, and halts on any failure. It never downloads arbitrary mirrors or silently drops records. If the provider distributes archives instead of individual files, use the provider's authorized extraction instructions and verify paths and identity metadata separately. Actual full files, identity sidecar, subset composition, label balance, feature extraction, training and held-out metrics remain unavailable in this environment. No detector has been trained. The classifier consumes separately pooled pretrained features and is not a validated synchronization model, AV-Lip-Sync+ reproduction, or DTW system.
